# Final design, after five independent critics

Critics: foundation (faithfulness), metric-on-design (hard to vary applied to the design), owner-intent (does it do what was asked; metric wherever claims are made), operability (will it run), history-walk (all 47 errors walked through it). Each finding below is applied or rejected with a reason. This ledger is the review record for the design.

## What changed from the draft, and why

1. **"Built in" is claimed per mechanism, with a declared boundary** (foundation, blocking). Boundary: the repository's files, the processes Claude Code and git run from them, and agents while they work in the repository. Continuity: a result holds for a named commit. Every mechanism is sorted into *runs by itself* or *runs if an agent follows it*, and each of the second kind leaves a trace a script checks. CLAUDE.md carries the table. The process is tried on planted problems with and without the build before it is called built in; until then it is "written, not shown to run". APPLIED.
2. **Review receipts at commit** (operability, history-walk, blocking; metric-on-design agrees in substance). A staged change to skill text, agent files, CLAUDE.md, kept cases, or an owner-facing numbered write-up is refused unless `.claude/reviews/<fingerprint>.md` exists for that exact change, from a reviewer agent that did not make it, or a light receipt ("no meaning change", with the maker named and a reason). Any later edit changes the fingerprint. This turns a skipped review (H30, H31, H41: the history's costly pattern) from a silent slip into a false statement in a kept file. APPLIED.
3. **The gate is git's own pre-commit hook** in a committed `.githooks/` folder, switched on at session start (`git config core.hooksPath .githooks`), checking the staged snapshot, failing closed if python3 is missing (history-walk and operability, blocking: 5 of 19 real commits edited and committed in one command, including H38's). A small Claude hook refuses `--no-verify`. The earlier PreToolUse commit hook is dropped. APPLIED.
4. **Weight by reach, with named tripwires** (all five). Three weights: no meaning change (fix, gate, light receipt); a meaning change from a review (one ledger line per finding, applied or rejected with a reason, in the review receipt); the full correction, recorded in the corrections file, only when a tripwire fires: the owner caught it or a writer's objection stood; a kept case or a check failed for a reason outside the change being made; a kind got past the catch the corrections file names; the error is in a check, a brief, a theory reading or a record; or it had already reached the owner. APPLIED.
5. **The loop is six steps and a five-field record** (operability, metric-on-design). Steps: freeze; criticise and measure; locate; plan; change and show; guard and record. Fields: made by and found by; the criticism and its verdict; where it got through and the response; fixed, still working, lost, with receipts and attribution; what catches it now and what would reopen it. APPLIED.
6. **Words** (operability, foundation, owner-intent). *Sign* (not signal, as hard-to-vary says). A criticism has target, defect, grounds and **connection**; **bears / does not bear yet / does not bear** is the verdict (foundation K1). *Correction* is one run; *change* is what is made (craft skills keep "fix" for stories); no *repair* as a term: three plain questions (fixed, still working, lost) plus "what shows the change did it". *Re-tune* or *build a new part* (hard-to-vary's words). *Held if* for a verdict that needs an input nobody gave (hard-to-vary's mark); *unknown* for missing evidence. *Kept case*, *quick version*. The file is **the corrections file** (`27 Corrections.md`); *register* stays the source register. No M or K codes in agent-facing text. APPLIED.
7. **The owner's wants are inputs; facts the owner states, and whether two wants can both be met, are open**; a conflict goes back as a question; an owner objection is never set aside, and if it looks loose the agent asks the question that would settle it (foundation, owner-intent). APPLIED.
8. **Locating the fault**: each place in the bundle (thing, rig, inputs) is a rival guess with the case that would separate it; prefer a change whose cost shows; a change to a part with no other job is labelled a patch and must earn a second job or stay open. "Smallest" and "breaks least" dropped; "one home, pointers elsewhere" kept (foundation). APPLIED.
9. **A return after a re-tune is a tripwire, not proof**: ask what every re-tuned version lacks and whether the re-tune reached the maker; build only when that part is named, and record its witness (what it is, what it binds, where it lives). Labelled the workshop's reading of Derivation 10 (foundation, metric-on-design). APPLIED.
10. **The repair check and the claim check are named apart from the metric**: whether a change works is judged by what it fixes, keeps and loses on stated occasions (Part XI); whether a claim stands is judged by receipts (Part IX). The metric is used where an explanation is judged: the criticism, the guess at where the fault is, the change's reason, a new rule's job, the "because"s in a claim, and craft rules and rivals when written. That this is where the metric belongs is labelled the workshop's reading of "hard to vary is a metric" (foundation). APPLIED.
11. **Three attributions** recorded for every full correction: fixed through an account; fixed without an account (the change works, the why is not yet held: a separate open correction on the account); account without a fix (foundation, Part XI). APPLIED.
12. **Two routes allowed**: a new mechanism names its error; if another already catches it, say what each guards against that the other does not (bypass, silent failure), or merge (metric-on-design, foundation). APPLIED.
13. **Derivation 3 in its revised form**: the change is run on a case where the nearest rival change (including the one-line patch and doing nothing) would differ (foundation). APPLIED.
14. **The metric where claims are made** (owner-intent, blocking): a **rule card** in add-source and in the change step (what holds the rule; remove it; swap any number or example; walk the owner theory's own cases), a **rival form** (each side with its source line; one outcome; both predictions; check they cannot both come true; status untested or run on <case>), a visible **self-check in every craft Reply** (the stock-note, flip and rival tests; the result shows as held by, free or unknown), and a **"Checks run on these notes"** section required in any critique or test write-up (check_records flags it). No mass edit of existing rules: a section gets the card when it is touched. First uses include plot's "at least twice". APPLIED.
15. **Term sheet** for the owner terms that kept drifting, each with its theory line, the words it gets confused with, a telling test and a question number; used by briefs and the theory-checker. Not a script (owner-intent, history-walk). APPLIED. A lower-case "horror" script: REJECTED; the current lower-case uses are quotes, file names, or arguable plurals, so a script would mostly raise false alarms.
16. **Brief check by the theory-checker, not the author**, one home in `reviews-and-briefs.md`, widened: credits and definitions quoted; readings and instructions tied to a theory line or labelled, and the theory's own case walked through them (H28); every pointer opened (H26); every template slot that assumes a distinction carries its telling test (H8); checker briefs free of the lead's findings (H43, H44). Kinds and term-sheet rows go into every brief (history-walk, owner-intent). APPLIED.
17. **Kept cases outside `.claude/skills/`**, in `kept-cases/`, never given to writers or fixers; the 8-word contamination guard is dropped (operability measured 0 hits on H33 and H32's sentence, 4 false alarms). Runs start from a clean committed state, return a stall report, record the commit and each skill folder's fingerprint, keep failures as they came, and include a planted wrong answer to test the grader. Session start warns when a skill has changed since its cases last ran. APPLIED.
18. **Status lines carry "(as of entry N)"**; check_records fails when any is older than the last entry. Old log entries unchanged except for added lines beginning "*Corrected in entry N:*". The log ends at "## Next step" (operability, history-walk). APPLIED.
19. **Frozen set** is the tracked .md files in sources/ other than README.md, plus the foundation; the fingerprint list is add-only; `--add` refuses a listed file (operability, foundation). The edit-refusing hook stays as a second route whose own job is refusing before the working copy is damaged (metric-on-design allowed it if shown to fire). APPLIED.
20. **Copying at commit**: staged files under sources/raw/, or any .txt or ebook file, are refused; when books are absent and a staged module names a book in its Sources line, the review receipt must say "Book text: none added, because ..." or the commit is refused (owner-intent, operability). APPLIED.
21. **Passage memory**: before changing a passage, look up earlier corrections of it (`git log -L`, the corrections file, the review receipts); a correction that rejected a reading leaves a marker at the passage ("not X: see C4") (history-walk, owner-intent). APPLIED.
22. **After a commit**, a Claude hook adds the claim check to the agent's context (operability). APPLIED if its output form is confirmed to work; otherwise recorded as untested.
23. **Say the request back** in one line before acting on an owner request, naming anything added; the log entry opens with the owner's words (history-walk, owner-intent; H45, H46). APPLIED, in CLAUDE.md.
24. **K2 for any withdrawn premise**: the "0 problems" map-check results since log entry 17 rested on a check that missed five of six planted faults; a new log entry withdraws their licence, and the repaired check has rechecked them (foundation). APPLIED.
25. **The history list is committed**, in own words, as an appendix of the corrections file labelled "rebuilt from working records on 24 September 2026", after the copying check (foundation, operability). APPLIED.
26. **No edit to hard-to-vary** (owner-intent: a pointer line names no error it catches, and the skill is the owner's). Its open items go to the questions file. APPLIED.
27. **No GitHub check without the owner's yes** (owner-intent: surprise and failure emails for a non-programmer; its jobs are held only if the owner edits on GitHub or reads pull-request ticks). Added to the questions file as S10. The other critics' case for it (a third-party receipt; commits made outside Claude Code) is recorded there. APPLIED.
28. **Checks on the checks**: whenever a check script, the fingerprint list or the allowed-titles list is staged, the gate also runs test_checks.py (operability, foundation). APPLIED.
29. **Removed as claimed jobs that did not hold**: stamp check for H34 (replaced by per-line stamps), section-pointer check for H26 (kept, credited only with planted faults), "numbered file has an entry" for H36 (kept, credited with H39 only), SessionStart for H1 and H34 (kept as a convenience that switches on the gate). O1 is not credited to the frozen check; its job is the owner's "not even typos" rule. APPLIED.
30. **Log entry required in every commit that touches skills** (owner-intent): REJECTED. A piece of work often spans several commits (entries 25 and 26), so a per-commit rule would force empty entries. The gap (H39) is recorded as on trust in the kinds table.
31. **book_to_text reports skipped parts** (owner-intent, audit 5): APPLIED if the change is small; it feeds the copying check.
32. **Stored theory compared with the supplied file before fingerprinting** (owner-intent, audit 1): APPLIED as one step in add-source Step 2 (a diff command), not a new script.
33. **Four reviewer agents**: theory-checker (fidelity, term sheet, the metric on new rules, rivals and examples, the cross-skill pull, briefs), use-tester (walks cases; red team; stall report; compares a change with the kept cases for the same scenario), copy-checker (books present), case-grader (with a planted wrong answer each batch). The owner-intent rival's two agents would merge theory-checker and use-tester; REJECTED because walking a case caught five blocking errors the fidelity reading missed (H5, H13, H15-H17), so the lenses do different jobs.

## Test plan

1. Kept cases run on the committed skills before any change (running now), and again after, with results kept as they came.
2. test_checks.py plants each fault each check claims, with innocent neighbours, and the real historical texts where possible.
3. A headless Claude Code run in a scratch copy, to see whether the hooks and agent files actually load and fire.
4. The process tried on two planted problems, predictions written first, in two conditions: the repository before this build, and after. Problem 1: the reversed villain ladder re-planted, with one restatement elsewhere, and the owner's sign "the villain ladder reads the theory backwards". Problem 2: the owner answers Q1 with option (a).
5. Independent review of the whole build (theory-checker and use-tester), producing the review receipts for its commits.
