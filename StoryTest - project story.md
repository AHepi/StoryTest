## How the pieces fit

A concrete case first. A writer asks, "My villain feels flat. Why?"

1. The `character` skill takes it. Its frame is your Bond theory: audiences care because of the relationship a story builds, and for a villain the enemy is indifference, not dislike.
2. It checks the villain against the theory's ten levers, and against ideas from Egri and Truby on building a cast, written in the workshop's words.
3. Each suggested fix is tested with the `hard-to-vary` skill: if the villain's backstory could be swapped for any other and nothing in the story changed, it is doing no work.
4. If the fix is in how the villain talks, the `dialogue` skill takes over; if it is in when the audience learns what the villain wants, the `plot` skill does.

And when the workshop itself is wrong: say a rule in the `character` skill misreads the Bond theory.

1. The `error-correction` skill turns the sign into a criticism (what is wrong, on what grounds), and measures it with hard to vary before anything changes.
2. It asks where the error got through, a brief, a template or a fix, and changes that stage too.
3. The change must show what it fixed, what still works (the kept cases for the character skill, rerun), and what it lost.
4. The commit gate will not save the change without a review receipt from an agent that did not make it.
5. The correction goes in `27 Corrections.md`, so the next brief carries the lesson.

The parts, what each does, and what it hands on:

| Part | What it does | Hands on to |

## Word list

- **Skill:** a folder of instructions that Claude Code loads when a request matches it. Each has a main file (`SKILL.md`) and optional extra files it opens only when needed.
- **Module (reference file):** one of those extra files, covering one part of a skill in depth.
- **Map:** the table and diagram near the top of each skill that says which module to open when. A module missing from the map can never be reached.
- **Owner theory:** one of the four theories you wrote (Implied World, Gap, Anticipation, Bond). The skills call them this. The primary source for a craft skill.
- **Frozen source:** a stored text that is never edited. A changed version is added as a new file, called a revision.
- **Foundation:** your formal theory of explanation ("Claude Fable Semantics"), which the hard-to-vary skill puts to work.
- **Craft skill:** a skill for one area of storytelling (world, plot, character, dialogue, genre).
- **Craft book:** a published book on writing. Registered and used in own words, never stored.
- **Register:** the list of sources in `sources/README.md`.
- **Own words:** written fresh from notes, not copied or reworded line by line from a book.
- **Overlap check:** a script that lists every run of 8 or more words in a row that the workshop shares with a book. The rule is zero, apart from titles, names and short terms.
- **Hard to vary:** a choice is hard to vary when changing it would break something the story needs. A choice you could swap for any other is doing no work.
- **Rival:** a book's view that differs from one of your theories, recorded beside the theory with a way to tell the two apart, never used to overrule it.
- **Commit:** a saved snapshot of the files, with a note saying what changed. **Push:** sending commits to GitHub. **Branch:** a separate line of work. **Pull request:** a request to fold a branch into the main line, where changes can be reviewed.
- **Agent:** a separate Claude worker given one job. **Workflow:** a script that runs many agents to a plan.
- **Error correction:** how the workshop finds and removes its own errors, as a process that runs through all its work: the `error-correction` skill. **Hard to vary** is the metric it uses whenever it judges something.
- **Sign:** anything that suggests an error (a failed check, a reviewer's finding, your objection). A sign is not yet a criticism.
- **Criticism:** a sign worked into four parts: the exact thing criticised, what is wrong with it, the grounds (a theory line, a case, a check's output), and how the grounds show it. A criticism **bears** when its account of the fault holds up; it **does not bear yet** when a fact that would settle it has not been checked or told.
- **Correction:** one run of the process, from sign to record. The full ones are in `27 Corrections.md`.
- **Re-tune; build a new part:** the two responses to an error. Adjust what exists, or add what was missing.
- **Receipt:** a pointer to what actually happened: the command that ran and what it printed, a commit, a reviewer's report. A record made from the claim, rather than from what happened, is not one, whenever it was written. A **review receipt** is the kept record of one review, with the reviewer's report pasted in.
- **Fingerprint:** a short code worked out from a file's or a change's exact contents. Change one character and the code changes.
- **Hook:** a small program Claude Code or git runs by itself at a set moment, such as before every commit.
- **Commit gate:** the hook that runs every check, and asks for a review receipt, before git will save a commit. It uses the checks as they were in the last approved commit, and compares with it, so a check cannot be loosened in the same commit as the work it would stop. It stops most honest mistakes and shortcuts, not all; it does not stop an agent set on getting round it.
- **Stamp:** a line the gate adds to each commit it passes, naming the exact contents it approved. A commit without a matching stamp is one the gate never approved.
- **Last approved commit:** walking back along the main line (each commit's first parent), the first commit whose stamp matches its contents, or a merge made on GitHub with no conflict that joins approved work. The gate compares everything with it, and everything before it is settled.
- **Staged:** marked with `git add` to go into the next commit.
- **Recheck:** a look, at the start of each session and before each commit, at the commits since the last approved one (made on GitHub, or with the gate skipped), for what only the history shows: each one's review receipt, a withdrawal it claims, book files, and changes to the gate's own files.
- **Kept case:** a short story problem with what a good answer must and must not do, written before any run, rerun after a skill changes.
- **Licence:** leave to rely on a passage. When something it rests on is withdrawn, such as a stopgap you answer, it loses its licence until rechecked; it does not become false.
- **Held if:** a verdict that depends on an aim or value only you or a writer can give; it is given both ways, and you are asked. **Does not bear yet** (for a part of an explanation, **unknown**): a verdict that needs a fact nobody has checked or told, such as which draft came first; the test or question that would settle it is named.
- **Rule card:** four questions every new rule in a skill must pass before it is written: what it rests on; what a writer would do differently without it; whether its numbers and examples could be swapped with no loss; and whether your theory's own cases survive it.
- **Rival form:** how a book's view that differs from your theory is recorded: both sides, one story change where they would predict different outcomes, and each side's prediction.
- **Term sheet:** the list of your terms that kept drifting, with your theory's own words and a test that tells each from its neighbour.
- **Stage:** one numbered folder in `stages/`, doing one job in making a story (the premise, the cast, the plot...). In the error-correction skill's sense each is also a stage where an error can get through.
- **Stage contract:** a stage's `CONTEXT.md`: what it reads (its Inputs table), what it does, what it writes, and what it checks.
- **Layer:** one of five levels of instructions, from `CLAUDE.md` (where am I?) down to a run's own files (what am I working on?); `stages/how-stages-work.md`, section 1.
- **Run:** one project going through the stages. Its files go in each stage's `output/<project>/`.
- **Review stop:** the pause after every stage, when you read, edit or redirect the work. (The paper says *review gate*; the workshop says *stop*, so it is never confused with the commit gate.)
- **Marker:** a short note in square brackets on each part of a stage's output, naming the step and the reference that produced it, so a fault can be traced back to its source.
- **Stale:** said of a stage's output when a file it read has changed since; not wrong, but not to be relied on until rechecked.
